# 手の子として使うチェーンソーの状態別姿勢設定

チェーンソーは手のボーンの直接の子にします。親変更はユーザー側で行います。SOの位置・角度は、手から見たLocal Position・Local Rotationです。手のアニメーションと左右反転を親から引き継ぎ、その上に状態別のローカル姿勢を適用します。

旧版のPlayer基準のSOとは数値の意味が異なります。新しいSOを作成してください。こちらではモデルやボーンを変更していないため、自動座標変換は行いません。

## ファイル更新

ZIP内の3本を、前回追加した同名ファイルへ上書きしてください。Unity側の既存.metaは残します。

- Runtime/ChainsawPoseData.cs
- Runtime/ChainsawPoseController.cs
- Editor/ChainsawPoseControllerEditor.cs

SO専用Inspectorも上記Editorファイルに含まれます。既存SensorPlayerController・SensorChainsawDiggingの差し替えはありません。Unity 6系のAPIを使用します。asmdefがある場合、Runtime側から既存ゲームクラスを、Editor側からRuntime側を参照可能にしてください。

## 初期設定

1. 武器全体のルートを手のボーンの直接の子にします。
2. 通常のTransformで基本の握り位置を合わせます。
3. Player上のChainsawPoseControllerへ以下を設定します。

| 項目 | 設定 |
|---|---|
| プレイヤー制御 | PlayerのSensorPlayerController |
| 食い込み制御 | PlayerのSensorChainsawDigging |
| Playerのルート | 既存ControllerとRigidbodyがあるPlayer |
| 手のボーン | 武器を直接ぶら下げた手。空欄なら武器の親を使用 |
| チェーンソーのルート | 子のMeshではなく武器全体のルート |
| 姿勢データ（SO） | 最初は空欄 |
| 移動姿勢にする速度 | 通常は初期値0.05 |

Playerのルートは状態参照と対象確認に使い、姿勢の座標基準には使いません。

4. 「現在の握り位置からSOを新規作成」を押し、保存先を選択します。
5. 全13状態へ現在の手基準の姿勢が登録され、SOが選択されます。

旧SOを割り当て済みなら参照だけを一度空欄にして新規作成します。旧SOを削除する必要はありません。ProjectのCreate → チェーンソー → 状態別の姿勢データから作ることもできますが、その場合はPlayerへ割り当て、確認対象を指定して初期化します。

## SOで状態別に調整

1. ProjectでSOを選択します。Playerの「このプレイヤーを対象にSOを開く」からも開けます。
2. 「調整する状態」で「壁への食い込み」などを選択します。
3. 「手からの位置（ローカル）」「手からの角度（度）」を編集します。
4. 「この姿勢への切り替え秒数」を設定します。0なら即時です。
5. 「SOを保存」を押します。

位置・角度は武器Transform InspectorのLocal Position・Local Rotationと同じ基準です。状態ごとの値はSOに保存され、実行時に自動選択されます。

## 再生せずにPrefabモードで確認

1. PlayerのPrefabを開きます。
2. Prefabモード内のPlayerを選び、「このプレイヤーを対象にSOを開く」を押します。
3. SOの「確認するPlayer」に対象が入っているか確認します。空欄なら、PrefabモードのHierarchyにあるPlayerのChainsawPoseControllerをドラッグします。
4. 状態を選択し、「この状態を武器にプレビュー」を押します。
5. SOの数値を変えると、実際の武器ルートとPivotに反映されます。W移動・E回転の専用ハンドルも使用できます。
6. 「プレビュー終了・元の配置へ戻す」で武器の元のTransformに戻ります。調整したSOの値は残ります。

表示用複製は作りません。UnityのAnimationModeで実際の武器ルートの位置・回転だけを一時表示します。SOの選択解除、Scene保存、Prefab保存・終了、再コンパイル、Play Mode移行でもプレビューを終了します。Prefab自動保存の直前にも終了処理を登録しています。

Animationウィンドウなど別のアニメーションプレビューとは同時使用できません。先にそちらを終了します。武器ルートにController未設定のAnimatorがある場合も、開始時にメッセージを表示します。

プレビュー中はSOを選択したまま専用ハンドルを使います。通常のTransformから取り込みたい場合はプレビューを終了し、武器を手動調整してからSOを選び、「武器の現在のTransformをこの状態に取り込む」を押します。取り込むのは位置・回転だけです。

「確認するPlayer」はEditorの一時参照であり、SOへScene参照を保存しません。再コンパイル後などは指定し直します。Project上のPrefabアセットではなく、開いたPrefabモードまたは通常SceneのPlayerを指定します。

## 切り替えの動き

プレビュー開始後、「切り替え元の姿勢」を選び、「設定秒数で切り替えを確認」を押します。選択中の状態が切り替え先です。進行度スライダーでも確認できます。ハンドル編集時は進行度を1にします。

位置はLerp、回転はSlerp、進行度はSmoothStepです。実行時に補間中の状態が変わると、その時点から次の姿勢へ移行します。

## 攻撃1～3段目

「地上攻撃」を複製し、「対象の攻撃データ」に既存ControllerのSlash1・Slash2・Slash3と同じAttackDataをそれぞれ指定します。空欄は共通姿勢です。空中攻撃も同様です。

攻撃データが一致する専用姿勢を優先します。各段が同じAttackDataを共用している場合は区別できません。名前だけで段を識別する機能はありません。同じ条件の重複は警告します。

## 状態の分類

優先順位は強衝突硬直 → 回避 → 攻撃 → 食い込み面 → 食い込み要求 → 空中上昇／下降 → 移動／待機です。

| 既存公開情報 | 姿勢 |
|---|---|
| IsImpactStunned | 強衝突の硬直 |
| IsEvading | 回避 |
| IsAttacking・CurrentAttackData・IsGroundedForCamera | 地上／空中攻撃 |
| Surface | 床・壁・天井・敵への食い込み |
| IsRequested、Surfaceなし | 食い込み要求・接触待ち |
| 非接地、linearVelocity.yが正 | 上昇 |
| 非接地、その他 | 下降 |
| 接地、横速度が設定値を超える | 移動 |
| 接地、その他 | 待機 |

攻撃中の接地判定は現在の値であり、開始時の非公開フラグではありません。着地すると地上攻撃姿勢に変わります。死亡・壁ジャンプ準備は独立分類していません。接触なしの地上食い込みアニメーションだけが再生されIsRequestedが立たないケースにも専用姿勢はありません。未登録状態は実行開始時の手基準の配置へ即時復帰します。

## 注意点

- 手の子にするため、手のアニメーションは武器へ伝わります。独立設定するのは手に対するローカル姿勢であり、ワールド座標での姿勢固定ではありません。
- 左右反転は親から引き継ぎ、武器への追加180度回転は行いません。
- 1状態につき1姿勢と状態間の補間です。攻撃内の複数キーによる振りかぶり・振り下ろし編集は含みません。
- SOからキャラクターのアニメーションは再生しません。現在の手の姿勢に対する武器を確認する機能です。実際のモーションとの整合は実行して確認します。
- 武器ルートのローカルTransformをAnimation Clip・Constraint・他のスクリプトでも動かすと競合します。手のボーンだけが動くことは想定内です。
- スケールやモデルのPivotそのものは変更しません。子MeshのオフセットやスキンのBones参照も自動補正しません。
- 武器配下のCollider・エフェクトは一緒に動きます。別階層のDigging_Collider・SlashEffectRootは追従しません。刃と判定の整合を確認してください。
- 実行時処理はAwake・FixedUpdate・OnDisableです。Start・Update・LateUpdate・コルーチン・Invokeは追加していません。固定更新と描画の頻度差による段付きは実機で確認してください。timeScaleが0なら補間も停止します。
- この環境ではUnity Editorでコンパイル・再生・Prefab自動保存の実機検証を行っていません。

## 導入確認

1. コンパイルエラー・参照エラーがないこと。
2. 手を親にした武器が、手と左右の向きに追従すること。
3. SOの数値とプレビュー中の武器ルートのローカルTransformが一致すること。
4. ハンドル編集をUndoで戻せること。
5. プレビュー終了・Prefab保存後に武器の配置が戻り、SOの調整値は残ること。
6. 各行動で正しい姿勢が選ばれること。
7. ダメージ・食い込み判定・エフェクトの位置が見た目と合うこと。
